The important design fact: they already talk — through structured paper, not conversation. Kyla's "handle with care" notes reach Moon. The directors' takes are merged and de-duplicated before Moon reads them. His purchases reach Kyla's chat. This is how restaurant kitchens work: tickets, not meetings.

The huddle question

Moon already is the huddle

A literal huddle agent — everyone "meets" before the plan is written — sounds right and prices wrong. Every extra meeting is a serial model call: +6–15s a customer feels, for information Moon already receives in full. He is the one staff member who reads everybody's work before deciding anything; adding a coordinator above him duplicates his job and slows the kitchen.

The principle for this app: improve the tickets, not the meetings. Every idea below follows it — richer handoffs, better timing, more memory — and almost none of it adds a second to the customer's wait.

Recommended builds

What to build, in order

Build first · zero latency · business-critical

1. The analytics ledger

A fire-and-forget event log (interview started, plan finished, plan saved, store recommended, outfits opened) written to disk — no model calls, no customer-visible cost. This is the receipt book for the entire store-partnership business: "we sent Hamilton Shirts 14 fitted customers this month" only works if it's counted. Right now nothing is counted.

Build second · zero latency · customer memory

2. The full dossier behind claim codes

Claim codes currently save the profile, plan, and purchases. Add the photo assessment, the plan-chat history, and the outfit matrix, and a returning customer gets his whole file back — Kyla remembers the conversation they already had. This is the "come back next season" foundation, and it's an extension of a system that already works.

Build third · zero latency · quality floor

3. The deterministic inspector

Code, not an agent: after Moon writes a plan and before the customer sees it, mechanical checks run — banned colors appearing in items, made-to-measure lead times inside an urgent phase, plan total wildly off the stated budget, a store id that isn't in the directory. Failures trigger the existing auto-retry. The budget-math check already works this way and has caught real errors; this widens the net for free. An agent "editor" doing the same review would cost +6–10s per plan — build the code version, keep the agent version in the drawer.

Build fourth · zero latency · sharper handoff

4. The typed client brief

Kyla's most important intelligence — his goal in his own words, urgency, sensitive topics, quick wins — currently travels as free-text notes with agreed prefixes. Formalizing them as named fields in her submission (goal, urgentEvent, handleWithCare, quickWin) makes the handoff un-droppable: Moon and the inspector can rely on structure instead of parsing prose. Small change, permanent reliability gain.

Build fifth · seasonal cadence · fresher data

5. Timed pulls beyond monthly

Ryan runs monthly. Two additions: a weekly sales pulse during the windows that matter (November–December, July markdowns) refreshing only the price brief and hot store notes; and a pre-event sweep two weeks before CERAWeek, OTC, and rodeo season. Both are one-line schedule additions to the existing workflow — the machinery already exists.

Worth building · tiny cost, once per customer

6. The late-photo courtesy pass

The directors start work the moment the interview ends — usually before Watt finishes reading photos. That's the right trade (it's why plans feel fast), but it means frame and collar picks lean on stated preferences alone when the photo lands late. A cheap fix: when Watt's read arrives after the directors finished, re-run only the accessories director with the face data — ~4s, hidden inside the planner's minute, only when photos were actually uploaded.

Considered and rejected

Ideas that don't earn their latency

  • A huddle/coordinator agent — duplicates Moon, costs +6–15s, adds a failure point. The tickets are the meeting.
  • Agent-to-agent live chatter (directors querying each other mid-run) — multiplies calls and wait time; their outputs already meet on Moon's desk. Kitchens fall apart when the line cooks hold conferences.
  • Live web search during plan generation — would make every plan +15–30s slower and non-deterministic. Ryan's researched briefs exist precisely so runtime never searches. Keep research offline, on a schedule.
  • An agent QC editor on every plan — the deterministic inspector catches the mechanical failures free; save the model-review pass for when real-user plans show failure modes code can't catch.

The through-line

One sentence to build by

This app got fast by making the agents do their talking on paper, in advance, and off the clock — every future improvement should deepen the paper, the timing, and the memory, and treat any new meeting as guilty until proven innocent.

Validated this session across five customer types — a terse first-jobber, a western oil-field manager, a three-week groom, a decide-everything remote developer, and a standard run — the current back of house held: exact budgets five for five, urgent rules firing, zero errors, plans in 54–78 seconds. The list above is how it gets stronger without getting slower.
